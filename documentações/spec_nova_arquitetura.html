Especificação da Nova Arquitetura

Versão 2.0 31/07/2026 Gmail API + IA Classificadora

§1 O que é o Oráculo 360

O Oráculo 360 monitora os e-mails trocados entre a Finaud e seus clientes. O sistema tem quatro peças:

  1. Leitura do Gmail — acessa a caixa de e-mail diretamente via Gmail API e lê todas as conversas
  2. IA classificadora — entende cada e-mail e identifica a qual categoria ele pertence — obrigações regulatórias (como DDR, DRM, DLO) ou suporte — sendo que um mesmo e-mail pode envolver mais de uma categoria ao mesmo tempo
  3. Painel operacional — mostra ao gestor o que está aguardando ação (da Finaud ou do cliente) e o que já foi concluído, por categoria
  4. IA assistente (2ª fase) — aprende com os casos já resolvidos para ajudar a equipe a entender como tratar situações parecidas no futuro
✅ Decisão confirmada por Michel (22/07/2026): o sistema usará Gmail API direta para leitura dos e-mails em produção. O Gmail MCP continua disponível como ferramenta de análise durante o desenvolvimento.

§2 O que o sistema faz

  • Monitora todas as conversas na caixa oraculo@finaud.com.br
  • Identifica automaticamente a qual categoria cada e-mail pertence (pode ser mais de uma)
  • Define o status de cada conversa — aguardando ou concluído
  • Monitora prazos regulatórios

O sistema ficará em execução permanente, atualizando automaticamente quando chegarem threads novas ou quando threads existentes receberem novos e-mails.

O que o sistema não faz

  • Não gera os CADOCs — só monitora a entrega
  • Não integra com o sistema interno da Finaud
  • Não cobre WhatsApp, telefone ou outros canais

§3 As 12 categorias

O sistema monitora 12 categorias de e-mail. O detalhamento completo de cada uma — como a IA reconhece, regras de status e exemplos reais — está no §14.

CategoriaO que é

DRM 2060Relatório mensal que mede a exposição da instituição a riscos de mercado — juros, câmbio e preços de ativos.
DLO 2061Relatório mensal sobre os limites regulatórios do conglomerado — adequação de capital (Basileia) e concentração de riscos.

DRL 2160Relatório mensal do "colchão de liquidez" — quanto de ativos líquidos a instituição mantém para cobrir saídas em situações de estresse.

§5 Como os e-mails chegam ao sistema

A conta oraculo@finaud.com.br recebe os e-mails por dois caminhos independentes:

CaminhoComo funciona
1 — Grupo de suporte A conta oraculo@ é membro do grupo suporte@finaud.com.br. Todo e-mail enviado para suporte@ chega automaticamente também na caixa do oraculo@, da mesma forma que chega para qualquer outro membro do grupo.
2 — Cópia automática (Workspace) O Google Workspace está configurado para enviar uma cópia silenciosa de todo e-mail recebido por qualquer endereço @finaud.com.br para a conta oraculo@. Essa configuração fica no painel de administração (Gmail → Roteamento padrão) e é transparente: os colaboradores não fazem nada, os clientes não veem.

Resultado: mesmo quando um cliente escreve diretamente para rodrigo.tiberio@finaud.com.br ou andrea.inacio@finaud.com.br — sem copiar o suporte@ — o oraculo@ ainda recebe o e-mail pelo Caminho 2.

✅ Verificação feita em 31/07/2026: encontramos e-mails de clientes externos na caixa do oraculo@ enviados diretamente para colaboradores, sem nenhum campo (Para, CC ou BCC) com suporte@finaud.com.br. O Caminho 2 está ativo e funcionando.

§7 Dado sensível e segurança

Os e-mails contêm dados regulatórios de instituições financeiras — posições, saldos, relatórios de risco. Regras:

  • Nada vai para nuvem de terceiros (exceto o texto enviado à API Claude para classificação — sem dados numéricos brutos)
  • Credenciais Gmail ficam no .env local — nunca no git
  • Backups seguem o padrão data/json/pipeline/backups/AAAAMMDD_HHMM_motivo/

§10 Campos que cada e-mail precisa ter

Para classificar e rastrear corretamente, o sistema precisa extrair estes campos de cada mensagem:

Campo 1 — De (remetente real)
O endereço de quem enviou o e-mail. A Gmail API devolve o endereço real (ex.: noe.santana@amarilfranklin.com.br). Se for @finaud.com.br = colaborador Finaud. Qualquer outro = cliente ou externo.
Campo 2 — Para (destinatário)
Para quem o e-mail foi enviado. Em geral suporte@finaud.com.br ou o e-mail pessoal de um colaborador Finaud.
Campo 3 — CC (cópias)
Lista de endereços copiados. Usado para identificar outros participantes da thread. O oraculo@finaud.com.br aparece aqui quando a conversa foi copiada para captura.
Campo 4 — Reply-To
Para onde as respostas devem ir — campo presente na Gmail API, ausente no MCP. Importante para identificar caixas compartilhadas como remetente real.
Campo 5 — Assunto
O título do e-mail. Principal sinal de categoria para a IA. Padrões: código CADOC direto (DDR 2011, DRM (2060)), nome do documento (Balancete de Câmbio), tipo de situação (REJEITADO, INDÍCIO DE PROBLEMA).
Campo 6 — Corpo ✅ Concluído (30/07/2026)
O texto limpo que a IA lê para classificar. Antes de chegar na IA, o sistema aplica 8 regras de limpeza (L1–L8) em todos os e-mails de todas as 12 categorias — removendo assinatura, histórico antigo, rodapé e imagens decorativas.
6.989 e-mails · 12 categorias · regras escritas em §10
L1 Assinatura · L2 Histórico traços · L3 Histórico > · L4 Rodapé automático · L5 Imagem decorativa · L6 Imagem genérica (OCR) · L7 Imagem pós-assinatura · L8 Corpo vazio
Campo 7 — Anexos ✅ Concluído (31/07/2026)
Nome de cada arquivo em anexo. O sistema usa apenas o nome para classificar — não abre nem lê o conteúdo, exceto RETORNO_BACEN (OCR). Validado com 8.825 e-mails e 78.087 arquivos em disco.
ZIP do CADOC (altíssima confiança): padrão CNPJ_CADOC_DATA.zip → identifica categoria imediatamente.
Substituição: sufixo _S_N no nome = correção solicitada pelo BACEN (351 casos). Regex já captura.
COSIF (DLO 2061 / DLI 2062 / S5 / FORCAPITAL): chega em 3 formatos — .xml direto (642), .bc antigo (123), ZIP genérico. Com planilha LEC = DLO; sem LEC = DLI.
Formatos especiais: .rar (6) — mesma lógica do ZIP · .eml (8) — e-mail encaminhado, extrair conteúdo interno · sem extensão (BACEN): ADRM060-...=DRM, ALIM262-...=DLI.
Campo 8 — Thread ID e Data ✅ Concluído (31/07/2026)
Thread ID = chave de agrupamento da conversa (100% preenchido). Dois campos de data: data_email (sempre) e data_competencia (extraída pela IA; null = sem monitoramento de prazo). Inferência de ano validada em 157 casos. Threads de canal: 3 tipos definidos (entrega recorrente / coordenação / caso complexo).

§11 Regras de classificação

11.1 — Prioridade dos sinais

A IA usa os sinais em ordem de confiança: (1) Código CADOC no assunto; (2) Padrão de nome de anexo; (3) Conteúdo do corpo; (4) Histórico da thread. Sinais de alta confiança (ex.: ZIP CNPJ_2011_DATA.zip) sobrepõem sinais ambíguos.

Cliente enviou dados — aguarda Finaud processarFinaud

BACEN comunicou — aguarda ação de qualquer parteDepende de quem respondeu por último

11.5 — Regra universal: frases de cortesia após entrega = Concluído

Confirmado por Michel (29/07/2026). Aplica a todas as 12 categorias.

Se o arquivo foi entregue e a mensagem seguinte — de qualquer colaborador da Finaud ou do cliente — contém apenas frase de cortesia, agradecimento ou assinatura padrão sem novo pedido, a thread é Concluída.

FraseInterpretação correta
"Desde já agradeço e permaneço à disposição" (assinatura do colaborador Finaud)Encerramento cortês após entrega — não é pedido
"Obrigada", "Obrigado", "Valeu", "Perfeito", "Ok", "Recebido" do clienteConfirmação de recebimento — não reabre o caso
Qualquer frase de fechamento padrão sem pedido explícitoA cortesia não cria pendência
⚠️ O caso só reabre se houver pedido, dado novo, problema ou reclamação explícita na mensagem.

§12 Modelo de rastreamento (duas camadas)

Um e-mail pode tratar de mais de um CADOC ao mesmo tempo. O sistema registra cada entrega separadamente:

CamadaO que rastreiaExemplo
Camada 1 — E-mailA comunicação: quem enviou, quando, o que disseThread "Segue DDR, DRM e DLI — Mirae março/2026"
Camada 2 — EntregasUma linha por CADOC mencionado, com prazo próprioDDR_2011 + DRM_2060 + DLI_2062, cada um com seu prazo e status
Por que duas camadas? Sem isso, um e-mail com DDR + DRM + DLI geraria apenas uma entrada no painel. Os prazos são diferentes — misturar resulta em entregas perdidas.
